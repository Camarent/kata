# config

## Purpose
Load `config/kata.example.toml`-shaped TOML into a frozen `Config`. Every tunable value (ports, lease time, model endpoint) comes from here, not from literals in code.

## Key files
- `core/kata_core/config.py` - loader, `Config`, cast rules.
- `config/kata.example.toml` - reference values; every key must exist here. M26 keys: `[models]` (`cloud`, `local`), `[provider_openai]` (`api_key_env` = `KATA_OPENAI_API_KEY`), and `vision` in the provider tables. `[exam_mode]` (`idle_timeout_seconds`, `analysis_lease_seconds`, `lane_max_items`, `max_question_chars`, `max_name_chars`) and the `exam_analyse` routing and local capability entries are local only; `exam_analyse` is never a cloud class.
- `deploy/kata.host.toml` - host config template for the VM stack (M6). Its keys must exist in the example file: `scripts/deploy/validate_stack.py:195` `check_config_keys` checks it, run by `scripts/deploy/validate_stack.py:208` `main`.
- `deploy/env/small.env` (3 GB VM) and `deploy/env/large.env` (real server) - named memory and CPU profiles, passed to compose with `--env-file` (see `docs/deployment.md`, Profiles).
- `core/kata_core/api/deps.py` `require_feature` - feature sections with `enabled` (`[trainer]`) gate their routes.

## Invariants and gotchas
- Env override keys cast to the type of the TOML template value; a bad cast raises `ConfigError`.
- Database password is never in the file: `[database] password_env` names the env var that holds it.
- Missing key raises `ConfigError` naming the key; no silent defaults.
- Adding a key: add it to the example file and to the settings table in `docs/configuration.md` (checked by `tests/foundation/test_docs.py`; that file also pins the decision headings in `docs/decisions.md` and the exam-mode screen table in `docs/design/exam-mode-screens.md`, not the config keys).
